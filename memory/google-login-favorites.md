Added on 2026-08-28 (branch `profiles`): "sign in with Google, save favorite sessions".

- **Auth**: Auth.js v5 (`next-auth@beta`), Google provider, JWT sessions. Config in `auth.ts`; route handler `app/api/auth/[...nextauth]/route.ts`.
- **Storage**: Cloudflare D1 binding `DB` (wrangler.jsonc + `migrations/`). `users` keyed by our own random `usr_…` id (`lib/id.ts`), never Google's `sub`. `favorites(user_id, session_key)`. Ticket + check-in data lives in its own **`tickets` table** (migration `0004`, keyed by `email TEXT PRIMARY KEY COLLATE NOCASE`: booking_id, payment_id, ticket_url, ticket_name, addons, checked_in 0/1, check_in_time unix-ms, created_at, updated_at — `invoice_url` was added then dropped in `0007` for privacy, invoice PDFs carry billing name/address/GST). Migrations 0002/0003 added these as `users` columns first; 0004 creates `tickets` and DROPs them from `users`. Rationale: the ticketing provider (KonfHub) and Google sign-in only share *email*, and a purchase webhook can arrive before the buyer ever signs in — so email-keyed `tickets` lets the webhook do a plain upsert with no dependency on account creation. App reads via `lib/tickets.ts` `getTicketForUser({id,email})` — an explicit `ticket_claims` link (migration `0006`) wins, else a direct email match; `tickets` is read-only from the app, the ticketing Worker owns writes. Profile page: `checked_in === 1` → plain-text welcome block (title + socialise line + "Checked in at <venue-time>") between header and agenda section; ticket present → "Your DevFest ticket" (Booking ID copy pill + View ticket / Invoice glow buttons + "Not seeing the right ticket? Edit" → claim form); no ticket → claim prompt.
  - **`ticket_claims`** (migration `0006`): `user_id` PK, `ticket_email` (COLLATE NOCASE, UNIQUE), `booking_id`, `created_at`. `claimTicketForUser` matches `tickets` on `booking_id` **AND** `email` (2-field form — booking id alone is guessable) → `linked` / `unlinked` (own email → claim deleted, direct match resumes) / `not-found` / `taken`; never mutates `tickets`. Worker `applyCancel` deletes the claim in the same batch when it deletes the `tickets` row. `app/profile/actions.ts` `claimTicket` is real; verified end-to-end.
- **Session key**: agenda.json has no ids — `lib/session-key.ts` derives `track@start`.
- **Client**: `components/favorites/FavoritesProvider.tsx` (optimistic toggle, fetches `/api/favorites`), `FavoriteButton.tsx` wired into `AgendaList` + `AgendaBoard` focused card. Providers mounted in `app/layout.tsx`.
- **Pages**: `/signin`, `/profile` (shows name/email/shortened UID + copy, saved count, sign out), `/my-agenda`. Signed-out `/profile` AND `/my-agenda` server-redirect to `/signin?callbackUrl=<path>`. All three noindex + robots-disallowed + excluded from sitemap (`SiteRoute.noIndex`).
- **Post-sign-in redirect**: `lib/safe-redirect.ts` — `safeInternalPath()` (same-host path only, blocks open redirects: `//`, `https://`, `/\`, `%2f` etc.) and `currentInternalPath()` (client, "send me back here"). Applied in `SignInButton`, `SignInPanel`, `AvatarButton`, `FavoritesProvider` toast, and `auth.ts`'s `callbacks.redirect`.
- **Nav**: `AuthButton` (lite Header pill + hamburger menu list) links "My profile" → `/profile`. Plus `AvatarButton` — a glow-btn avatar docked left of the hamburger (full mode only, mounted in HamburgerMenu, faded out while panel open): signed in → Google avatar → `/profile`; signed out → user glyph → `/signin?callbackUrl=<current path>`.
- **Signed-out star click**: shows a dismissible "Sign in to save sessions" toast (rendered by `FavoritesProvider`), not an immediate Google redirect.
- Display-name feature was built then removed per user request; `users.display_name` column still exists but is unused (always null).
- `/signin`, `/profile`, `/my-agenda` mount `<BracketsField mode="settled" />` AND are listed in `BRACKETS_FIELD_ROUTES` (BracketsField.tsx) — required together, else the footer logo shows doubled brackets (flat 2D pair over the 3D pair). Lite mode → flat 2D logo; full mode → 3D logo only.
- **`workers/ticketing/`**: standalone Cloudflare Worker (`name: devfest-ticketing`) in-repo but NOT part of the app — own `wrangler.jsonc` / `tsconfig.json` / `src/`; excluded from root `tsconfig` (`exclude: ["node_modules","workers"]`) and `eslint.config.mjs` (`workers/**`); nothing under `app/` imports it. Binds the **same** D1 (`DB` → `devfest-chennai-2026`); owns every write to `tickets` (app only reads via `lib/tickets.ts`). Root scripts `worker:ticketing:{dev,deploy,types,check}` (dev passes `--persist-to .wrangler/state` so it shares the app's local D1). Migrations owned by root. **Run `npm run dev` and `npm run worker:ticketing:dev` one at a time** — two Miniflare instances on one state dir poisons the Next dev server's D1 stub (`Attempted to use poisoned stub` in `lib/db.ts`); fix = restart `npm run dev`.
  - **KonfHub webhooks** — one URL, no auth; access control is the unguessable path in the `WEBHOOK_PATH` secret — REQUIRED (unset → every request 404s, no `/webhook` fallback; dev reads it from `workers/ticketing/.dev.vars`). `src/konfhub.ts` parses (attendee email is the long `"Email Address(…"` key, lowercased; `CheckIn Time` string parsed as **UTC**). `src/store.ts` applies per `Event Type`: **registration** = upsert full ticket (booking/payment/ticket_url/ticket_name/`addons` JSON), keeps check-in, ignores if a different booking already stored; `ticket_url` kept only if it parses as `https://` (guards stored XSS from a forged webhook); **cancel** = main-booking-id match → delete row; else ticket-name match → no-op (manual mapping); else add-on-id match → drop that add-on; else no-op; **check_in** = set flag+time, create bare row if none; **check_out** = clear flag+time. Response codes tuned to KonfHub's retry set (500 only on real errors, 200 for processed/skipped, 4xx for bad request). `src/constants.ts` has the official ticket-name lists (sanity logging only). `samples/*.json` for local `curl` testing. Migration `0005` added `tickets.ticket_name` + `tickets.addons`; `0006` added `ticket_claims` (see Storage above).
- **AGENDA_READY gate**: when `AGENDA_READY` !== "true", `/my-agenda` calls `notFound()` (like `/agenda`), it's dropped from `siteRoutes` (moved inside the AGENDA_READY conditional), and the profile page's "saved sessions" section is hidden (`{AGENDA_READY && …}`). The ticket section and everything else on `/profile` stays.
